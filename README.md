## 云应用部署：不敲命令，等两三分钟就能对话

整个流程五步，没有一步需要碰命令行。

1. 打开安装页，填应用名称，选算力类型（HAI 或 CVM）。
2. 选部署地域和算力方案（HAI），或选可用区和云服务器类型（CVM）。
3. 在资源确认页核对后续要消耗的资源清单，点「下一步：安装应用」。
4. 等应用部署完成，页面自动跳到应用视图。
5. 再等 2–3 分钟，点右上角「打开应用」，进入 Web 界面后创建管理员账号。

账号密码自己保管好，这个 Open WebUI 的管理员账号没有找回入口。

端口是部署完最容易卡住的地方。HAI 算力下，Open WebUI 在 6699 端口，Chatbot UI 在 6889，JupyterLab 在 6888；换成 CVM 算力，Open WebUI 变成 8080，Ollama API 在 11434，而且只允许内网访问。想从浏览器直接进对话页，认准这组端口号，比在控制台里翻半天强。

CVM 部署还有一个额外能力：Ollama API。在应用视图的「安装信息」里能看到 API 地址，用 curl 调 `http://内网IP:11434/api/tags` 就能验证通不通。这个接口默认没有鉴权，如果不想让它裸奔，去安全组把 11434 端口禁掉。

## 模型选多大：1.5B 试水，7B 起步，32B 以上先看显存

同一个 deepseek-r1 标签下挂着七个尺寸，占用的磁盘空间从 1.1G 到 404G，差了两个数量级。

| 模型 | 占用空间 | 官方最低配置建议 | 备注 |
| --- | --- | --- | --- |
| deepseek-r1:1.5b | 约 1.1G | 未给出 | Qwen 蒸馏，适合先跑通流程 |
| deepseek-r1:7b | 约 4.7G | 8 核 16G、显存 8G | Qwen 蒸馏，单并发流畅的底线 |
| deepseek-r1:8b | 约 4.9G | 未给出 | Llama 蒸馏 |
| deepseek-r1:14b | 约 9G | 未给出 | Qwen 蒸馏 |
| deepseek-r1:32b | 约 20G | 未给出 | 无 GPU 机型无法运作 |
| deepseek-r1:70b | 约 43G | 32 核 64G、显存 80G | Llama 蒸馏，无 GPU 机型无法运作 |
| deepseek-r1:671b | 约 404G | 未给出 | 满血版，需要大显存多卡环境 |

官方只给了两档明确的最低配置：7B 要 8 核 16G 加 8G 显存，70B 要 32 核 64G 加 80G 显存。其余尺寸没写，只能按参数量往上估——这也是很多人踩坑的原因，觉得 32B 听起来不大，结果纯 CPU 机型根本拉不起来。

事实是，32B 和 70B 在没有 GPU 的机型上无法运作；7B 用无 GPU 机型能跑，但 token 输出速度会明显慢。想省钱又想要能用的速度，7B 配一张 8G 显存的卡是性价比最高的组合。

如果预算还没定，先用 1.5B 把整条链路跑通，确认端口、账号、访问方式都没问题，再换大模型。重新拉一个模型只是执行一条 `ollama run` 命令，不用重装整个应用。👉 [查看 HAI 各算力方案与当前价格](https://bit.ly/yunhuodong)

## 需要 API：TI 平台在线服务怎么开

TI 平台把 DeepSeek 全系模型上了大模型广场，走的是「新建在线服务」这条路径，产出的是一个带 HTTP 接口的服务，不只是网页对话框。

创建时几个关键选项：机器来源选「从 TIONE 平台购买」，计费模式选按量计费，部署方式选标准部署，模型来源选镜像，模型和运行环境选「内置大模型 / DeepSeek 系列模型 / DeepSeek-R1-Distill-Qwen-1.5B」这类内置项，算力规格参考案例是 12C44GB A10*1。填完点启动服务。

服务起来后，在「在线体验」标签页可以直接对话，不需要写代码。要接进业务系统，去「服务调用」页测接口：调用地址填 `/v1/chat/completions`，请求体里 `model` 填服务组 ID（就是接口地址最后那一段），`messages` 按标准格式放角色和内容。

命令行大概长这样：

bash
curl -X POST https://你的服务地址/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "ms-xxxx",
    "messages": [{"role": "user", "content": "你好。"}]
  }'


TI 平台还提供免部署的在线体验入口，DeepSeek-R1 和 DeepSeek-R1-Distill-Qwen-1.5B 两款可以在模型体验标签页里直接对话。想先判断模型回答风格合不合适，从这里试最快，不用先掏钱开服务。

## 费用：哪些钱会一直烧，哪些能省

云应用本身不收费，模型和软件都来自开源社区，收的是背后的云资源。所以费用高低完全取决于你选了什么算力、开了多久。

HAI 按小时结算，单价跟算力方案挂钩；CVM 同样按小时结算，单价跟机型挂钩，公网带宽另外按实际流量计费。两边的共同点是：长期使用建议转包年包月，比一直按量计费便宜；不用的时候关机，关机后计算资源不计费，只收少量磁盘费用。

HAI 实例默认 10Mbps 带宽，每台附 500GB 流量包，对单人调试或小团队内网使用基本够。

有一个容易忽略的扣费细节：CVM 按量计费模式下，账户欠费 2 小时后才停服，停服前那 2 小时照样产生消耗。想彻底止损，主动关机比等它欠费停服靠谱。

## 六个容易踩的坑

1. **HAI 创建失败，等很久也出不来。** 这是调度不到算力导致的，卸载后重试，或者换个时间段。
2. **CVM 报 `understock`。** 所选可用区没有这款机型的库存，换可用区或换机型重新安装。
3. **Ollama API 默认没有鉴权。** 11434 端口暴露在公网等于把模型白送，去安全组禁掉。
4. **关机重启后访问不了。** 2025 年 2 月 5 日之后安装的版本已经改用 EIP 提供公网访问，不再有重启换 IP 的问题；更早的版本需要把访问地址里的 IP 换成服务器最新的公网 IP，或者提前把公网 IP 转成 EIP。
5. **新建的用户账号看不到模型。** 模型默认只对管理员开放，管理员登录 Open WebUI 后在「管理员设置 - 模型」里把可见性改成 Public。
6. **模型输出慢得离谱。** 大概率是拿无 GPU 机型跑了 7B 以上模型。勾选「只看 GPU 机型」或搜索 NVIDIA 重新选机型，速度差别很明显。

## 常见问题

**必须用 GPU 服务器吗？**
GPU 不是必须的，但能明显加快 token 输出速度。7B 用纯 CPU 能跑，32B 和 70B 在无 GPU 机型上无法运作。

**部署完从哪里进对话界面？**
应用视图右上角的「打开应用」。如果打不开，先核对端口：HAI 算力是 6699（Open WebUI）/ 6889（Chatbot UI），CVM 算力是 8080。

**能改成 80 端口访问吗？**
CVM 部署可以。登录服务器加一条端口转发规则 `sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080`，同时确认安全组放行了 80 端口。HAI 部署没有对应的官方说明。

**关机后还收费吗？**
计算资源不计费，磁盘收少量费用。但如果是关机不收费模式，重启后公网 IP 会重新分配，之前记下的访问地址就失效了。

**7B 和 70B 的差距值不值那个配置？**
70B 需要 32 核 64G 加 80G 显存，成本比 7B 高一个量级。如果只是内部问答、文档总结这类任务，7B 先跑起来观察效果，不够再升级，比一上来就堆 80G 显存理智。
